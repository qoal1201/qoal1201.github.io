# 0001. `CONTEXT.md` 를 따로 만들지 않는다

- **Status**: Accepted
- **Date**: 2026-08-20 (결정) / 2026-08-22 (기록)

⚠ 소급 작성이다. 결정은 2026-08-20 에 났고 이 문서는 그것을 옮겨 적은 것이다.

## Context

에이전트용 도메인 문서 관례는 레포 루트에 `CONTEXT.md` 를 두고 그 레포의 어휘·구조를 담게 한다. 탐색을 시작하기 전의 에이전트가 그것을 먼저 읽는다는 전제다.

이 레포는 전제가 다르다. 내부 어휘의 진실원이 `CLAUDE.md` 이고 **그 파일은 세션마다 자동으로 읽힌다.** 지금 `CONTEXT.md` 를 만들면 같은 독자에게 같은 어휘를 주는 두 번째 사본이 생긴다.

## Decision

**만들지 않는다.** 어휘는 `CLAUDE.md` 에 그대로 둔다.

## Consequences

- 표면이 하나로 유지된다. 규칙 하나를 고칠 때 두 곳을 맞출 일이 없다
- 대신 `CLAUDE.md` 가 계속 커진다. 자동으로 읽히는 파일이라 그 부피가 매 세션 비용이다
- 이 레포를 처음 여는 외부 도구가 `CONTEXT.md` 를 찾으면 못 찾는다. 루트 `AGENTS.md` 포인터가 그 자리를 대신한다

## 다시 열 조건

아래 중 하나라도 참이 되면 이 결정을 다시 연다.

1. `CLAUDE.md` 감축에 착수한다 → 그 작업 **안에서** 어휘를 걸러 `CONTEXT.md` 로 낸다. 감축의 판정 기준(「어제 바뀔 수 있었나」)으로 안 바뀌는 쪽에 남는 것의 상당량이 어휘 정의다
2. 감축이 **2026-09-20 까지 착수되지 않는다** → 어휘가 자동 로드 파일에 계속 갇혀 있다는 뜻이므로 감축과 분리해 먼저 낸다
3. `CLAUDE.md` 가 자동 로드에서 빠지는 변화가 생긴다 → 이 결정의 전제가 무너진다

## 근거

두 번째 사본을 만드는 것은 이 레포의 규칙 동기화 원칙(「규칙이 사는 표면을 전부 함께 고친다. 하나만 고치고 나머지를 두면 조용히 어긋난다」)이 금지하는 모양이다. 2026-08-20 에 그 표면을 일곱에서 여섯으로 줄인 직후라 되돌리는 셈이기도 하다.
