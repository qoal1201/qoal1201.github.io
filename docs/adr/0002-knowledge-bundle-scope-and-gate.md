# 0002. 지식 번들의 적용 범위와 검사 자리

- **Status**: Accepted
- **Date**: 2026-08-20 (결정·집행) / 2026-08-22 (기록)

⚠ 소급 작성이다. 형식 정의 자체는 여기 복제하지 않는다 — 진실원은 이웃 비공개 레포의 ADR 0024 이고 **그 문서는 공개되지 않는다.** 이 문서는 **이 레포에서만 정한 것**을 적는다.

## Context

`knowledge/` 번들을 깔면서 세 가지가 이 레포에서만 갈렸다. 무엇이 번들 대상인가, 신뢰 등급을 어떻게 다루는가, 검사를 어디에 거는가.

## Decision

**① 공개 사이트 본문은 대상이 아니다.** `paper-reviews/` · `experiments/` · `foundations/` 는 읽으라고 쓴 글이지 찾아가서 꺼내 쓰는 지식 카드가 아니다. `CLAUDE.md` 도 대상이 아니다 — 항상 읽히는 지시문이라 같은 이유로 성격이 다르다.

**② 신뢰 등급은 저장하지 않고 유도한다.** 손으로 적지 않는다. **소급 복원도 금지한다 — 아무도 대조하지 않았으면 `unverified` 가 참이다.**

**③ 개수 하한을 코드에 박지 않는다.** 하한은 `knowledge/index.md` 의 `min_concepts` 에서만 읽고, 선언이 없으면 하한이 없다.

**④ 검사는 pre-push 에 건다.** `.githooks/pre-push` 가 사이트 검사와 번들 검사 둘을 돌린다(합계 0.3초). `core.hooksPath` 로 켠다. **오류만 막고 경고는 안 막는다.**

## Consequences

- ③ 때문에 카드가 0장이어도 검사가 통과한다. 의도한 것이다 — 아래 근거 참조
- ④ 는 `--no-verify` 로 우회된다. 그리고 `core.hooksPath` 는 커밋되지 않으므로 **새 클론마다 한 번 켜야 한다.** 파일은 추적되고 스위치는 안 된다
- 번들 검사기의 자기검사(`--selftest`)를 자동으로 부르는 곳은 아직 없다. push 가 나르는 것은 내용이지 검사기의 정확성이 아니라서 훅에 넣지 않았다

## 다시 열 조건

- **이 레포에 실험 코드가 들어오는 순간** ④ 를 다시 연다. 지금은 발행 파이프라인 하나뿐이라 훅으로 충분하다
- `tests/` 가 자주 바뀌기 시작하면 `--selftest` 를 CI 에 건다. `tests/` 는 git 이 추적하므로 CI 가 볼 수 있다

## 근거

③ 이 제일 중요하다. 다른 레포 두 곳에서 하한 상수를 그대로 베꼈다가 **그 검사를 초록으로 만들려고 카드를 혼자 채우는 사고가 실제로 났다**(2026-08-20). 검사기를 만족시키는 것이 목적이 되면 카드 내용이 합의 없이 생긴다. 그래서 이 레포는 하한 없이 깔았고, 카드는 합의된 것만 등록한다.

④ 에서 지식 검사를 발행 워크플로가 아니라 훅에 둔 이유는 `knowledge/` 가 발행되지 않기 때문이다. 카드 하나가 사이트 배포를 막으면 결합이 틀렸다. 경고를 안 막는 이유는 문체 검사가 push 를 막으면 이 레포의 다른 규칙(「고쳐서 문장이 나빠지면 안 고친다」)과 부딪히기 때문이다.
