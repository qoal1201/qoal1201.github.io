# 이슈가 진실원이다

다음 할 일은 로컬 마크다운이 아니라 **GitHub 이슈**에 산다. 이유가 배선이다 —
레포 간 왕래가 **GitHub 크로스 레포 이슈 참조**로 확정돼 있는데 이 레포만 그 배선에서
빠져 있었다. 채택 시점에 이 레포의 이슈는 열린 것도 닫힌 것도 0개였다.

조작은 `gh` CLI 로 하고, 클론 안에서 실행하면 remote 로 레포를 알아서 찾는다.

★ **이 레포가 공개이므로 이슈도 공개된다.** 제목·본문·라벨이 전부 보인다. 그래서
문서가 무엇을 이슈로 올리고 무엇을 안 올리는지를 가른다 — 그 판단은 취향이 아니라
공개 여부에서 나온다.

# 트리아지 라벨

다섯이다: `needs-triage` · `needs-info` · `ready-for-agent` · `ready-for-human` ·
`wontfix`.

상류 스킬의 어휘를 **그대로** 채택했다. 형제 레포들이 같은 어휘를 쓰므로 **오른쪽
문자열을 바꾸면 그 정합이 깨진다** — 바꿀 땐 다른 레포의 같은 파일도 같이 본다.

⚠ **아직 아무것도 안 만들어졌다.** 이 레포엔 커스텀 라벨이 없고, 다섯은 트리아지가
처음 쓰일 때 생긴다.

# ★ 클론은 작업 사본보다 작다

이게 이 레포를 다룰 때 가장 자주 틀리는 자리다. **상당량의 작업 재료가 git 밖에 있다.**

`.gitignore` 가 빼는 것 중 성격이 다른 것들:

| 무엇 | 왜 안 올라가나 |
|---|---|
| 자동 로드되는 지시문 · 에이전트 스킬 설정 | 개인 작업 메모 |
| 논문 PDF 원본과 정독 노트 | 저작권·용량 |
| 세션 인계 보관본 · 작업 폴더 | 로컬 전용 |
| 렌더 산출물 · 캐시 | 생성물 |

결과가 두 가지다. **첫째, 클론만 받은 사람은 운영 규칙 원문을 못 본다** — 이 레포의
규칙을 인용하는 문서가 그 원문에 링크할 수 없다는 뜻이다. **둘째, 클론에서 생성된
문서는 더 작은 레포를 서술한다** — CI 체크아웃에서 도는 검사가 무엇을 못 보는지가
[지식 번들](../knowledge-bundle/okf-bundle.md)의 한계 절과 같은 뿌리다.

# OpenWiki 읽기 경계

이 위키를 생성하는 도구는 git 이 아니라 **디스크를 읽는다.** `.gitignore` 는 그것을 안
막는다. 그래서 별도의 `.openwikiignore` 가 읽기 경계를 세운다 — **기본이 전부 차단**이고
git 이 추적하는 최상위 항목만 되살린다. 새 비공개 폴더가 생겨도 자동으로 막히고,
틀리면 위키가 얇아지는 쪽으로 틀린다.

⚠ **그 경계로 닫히지 않는 것이 있다.** 상류 문서가 직접 말하듯 이건 **읽기 경계**라,
막힌 경로는 절대 안 읽히지만 **화제가 안 나온다는 보장은 아니다** — 허용된 증거(공개
커밋 메시지 등)로 추론될 수 있다. 그래서 생성 뒤 유출 점검이 선택이 아니라 절차다.

⚠ **경계는 실행 시작 시점에 고정된다.** 실행 중에 `.openwikiignore` 를 고쳐도 그 실행에는
반영되지 않는다. 넓히는 방향으로 몰래 바뀌지 않게 하는 설계이고, 반대로 **실행 중에
발견한 경계 결함은 다음 실행에서만 고쳐진다.**
