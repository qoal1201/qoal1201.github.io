# 무엇인가

`_data/field-map-corpus/` 는 프롤로그의 분야 지도 절에 실린 편수·비중·차트가 나온
자리다. 2026-07-03 자동 문헌 조사가 생성했고 나중에 이 자리로 옮겼다.

내용은 공개 논문의 서지 정보(OpenAlex ID·제목·제1저자·연도·인용수·게재처·DOI)와
거기 붙인 분류 라벨이다. CSV 둘과 JSON 넷, 그리고 조사가 생성한 보고서 원문.

# ★ 같은 코퍼스가 두 판 있다

| 파일 | 편수 | 무엇 |
|---|---|---|
| `corpus_714_dedup_before.csv` | 714 | 중복 병합 **전** |
| `corpus_649_dedup_after.csv` | 649 | 중복 병합 **후** — 발행 표가 쓰는 쪽 |

이 둘의 존재가 한때 실제 혼란을 만들었다. **본문이 병합 전 수치를, 표가 병합 후
수치를 써서** 같은 글 안의 두 숫자가 어긋나 보였다. 오류가 아니라 **전후를 섞어 쓴
것**이었고, README 가 그 대조를 명시적으로 적어 재현해 두었다.

여기서 나오는 규칙: **이 코퍼스에서 수치를 인용할 때는 어느 판인지 같이 말한다.**

# 근거가 없는 수치가 하나 있다

★ README 의 「한계」 절이 **발행된 글에 실린 숫자 하나에 근거가 없다**고 직접 적는다.
어떤 데이터 파일에도 그 레코드 수가 없고, 조사가 생성한 보고서의 서술 한 줄에만
나오며 계산 흔적이 없다.

이건 데이터의 결함이 아니라 **기록된 결함**이다 — 그 자리에 적혀 있으므로 인용하기
전에 확인할 수 있다. 이런 항목이 남아 있다는 사실 자체가 이 폴더의 값이다.

같은 절이 다른 셋도 든다: 분류 프롬프트 원문이 저장되지 않아 *"무엇을 측정으로
쳤는가"* 를 원문으로 인용할 수 없다는 것, 인용 힌트 JSON 을 만든 코드가 남아 있지
않아 앵커 논문 목록과 후보 규칙을 알 수 없다는 것, 그리고 인용수의 출처 문제.

# 인용수의 출처가 다르다

⚠ 이 코퍼스의 인용수는 **수집 당시 OpenAlex 기준**이다. 그런데 발행 글에서 논문별로
인용수를 적을 때는 **다른 출처**를 쓴다 — OpenAlex 는 프리프린트와 게재판을 별도
레코드로 두어 크게 과소집계하기 때문이다.

그래서 **코퍼스 안의 인용수와 리뷰 본문의 인용수를 같은 수로 놓고 비교하면 안 된다.**
둘은 다른 것을 센 값이다.

# ★ 함정 — 같은 714편에 분류가 두 벌 있다

`litmap_*` 계열은 TF-IDF 와 K-means 로 만든 **7개 스레드**이고, 여기 있는 `terrain_*`
계열은 LLM 분류와 인용 힌트로 만든 **6개 지역 + 기타**다.

**발행된 지도는 6지역 쪽이다.** 다른 쪽을 대조에 쓰면 숫자가 전부 어긋난다. 실제로
한 번 그렇게 어긋나 "원자료가 없다" 는 결론이 났던 적이 있다.

# 무엇이 이 데이터를 쓰나

프롤로그의 분야 지도 절과 그 절의 차트 두 장이다. 차트를 만드는 스크립트는
[그림 생성](figure-generation.md)의 마지막 절이 다룬다 — 그 스크립트도 이 데이터와
같은 시기의 죽은 파일명을 아직 들고 있다.
